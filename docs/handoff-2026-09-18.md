## 3. The two bugs that mattered

### The timeline endpoint had never worked

The first GOL ever marked came back `server:500`. Cause: `TimelineEntryResponse`
declares a field called `metadata` and reads it from the ORM row. On a
SQLAlchemy model `metadata` is the **table registry** — the column is
`metadata_` — so Pydantic received a `MetaData` object and validation failed.

Nobody had posted a timeline entry before: Ensaio 2 had no marks, Realness had
no marks, and the endpoint had **no API test**. The sync pushes marks *before*
the session, so one mark blocked the whole upload.

Fixed with `validation_alias="metadata_"` and `tests/test_timeline_schema.py`,
which validates a real `EventTimeline` row. `GET /api/events/{id}` with a
timeline would have failed the same way.

**Lesson recorded:** an endpoint with no test and no caller is an endpoint that
does not work.

### The privacy page promised a delete that did not exist

Answering the Play data-safety question "can users request deletion of *some*
data without deleting the account", the code was checked: no delete on a night
anywhere — no button, no repository method, no endpoint. The answer is no.

But `/privacidade` had said since 17/09, in both languages, *"também dá para
apagar uma sessão específica … sem apagar a conta"*. Never true. Same defect
class this project keeps counting, this time in the document the Play listing
points at. Corrected; **open item 35**.

## 7. Traps and rules, re-learned

### The merge rule, broken a sixth time

PR #63 was opened after the first commit, and the deletion page was pushed to it
afterwards. Felipe merged at the earlier commit, so **the page never reached
`main` while its URL was already pasted into the Play Console**. Recovered by
restoring the files from the orphaned commit and opening #64.

The rule is unchanged and is in `CLAUDE.md`: **do not open the PR until the work
is finished and pushed.** What was new is the cost — not a lost commit, but a
live form pointing at a 404.

### Verify PR state from GitHub, never from memory

Applied throughout: every merge link sent in this session was checked for
`merged: false`, `mergeable_state: clean`, and head SHA equal to the branch.

### The egress proxy

`tumtum.cc` and the Railway backend are **not reachable** from this container
(`CONNECT tunnel failed, 403`). GitHub's API is. Never claim a deploy is live
from here; ask Felipe or infer from the merge.
